# Contribution Guidelines

Thanks for wanting to improve the list. Please read this before opening a PR.

## Criteria for a new entry

Every entry must pass all three:

1. **It exists.** The link resolves publicly (no auth wall, no 404, not archived). For repos, the default branch has real content — not an empty scaffold or a README-only placeholder.
2. **It's documented.** A reader can tell within a minute what it does and how to install or use it. Skills should follow the [Agent Skills format](https://agentskills.io/specification) (a `SKILL.md` with a name and description).
3. **It's maintained.** Recent commits, responsive issues, or a clear "done and stable" state. Abandoned experiments and dead marketplaces get removed.

Quality over volume. This list is curated, not exhaustive — "works and is genuinely worth someone's time" is the bar, not "is on topic."

## How to submit

- One entry per pull request, added to the correct section in alphabetical order (by repo or page name).
- Format: `- [name](url) - Sentence-case description ending in a period.`
- Keep the description to one sentence that says what it does, not why it's amazing.
- If you're the author, say so in the PR — self-submissions are fine when they meet the criteria.
- To report a dead or unmaintained entry, open an issue or a PR removing it.

## What gets rejected

- Link shorteners, affiliate links, or landing pages that gate the actual content.
- Entries duplicating something already listed without a clear differentiator.
- Freshly created repos with no users or usage evidence — let it bake first.
- Anything that requires sending credentials or payment to evaluate.
